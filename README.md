# 简存 · 单店进销存工作台

**一个单文件、离线能用、数据自己攥着的单店进销存。**

打开一个网页就能记账；断网也能用；数据存在你自己的设备上，不经过任何人的服务器。

## 它解决什么问题

小店记账的麻烦，通常不是「没有软件」，而是**软件太重、太慢、太麻烦**。

- 一套进销存要装服务器、建数据库、配环境，还没开始记账先折腾一天
- 手机上开个单要点七八下，忙的时候干脆记在本子上，晚上再补
- 装着装着就放弃了，因为「记一笔」的成本比「不记」还高

这个工具的想法很简单：**把「记一笔」的成本压到最低。**

一句话就能开单——像平时说话那样打进去：

```
张三 螺母5个13元 电钻3个30元
```

回车，自动拆成两行放进待结算清单，核对后一次结算，库存、现金、欠款同时更新。

## 三步用起来

### 1. 打开

用手机或电脑浏览器打开部署地址（或自己下载 `index.html` 双击）。

> ⚠️ **不要在微信里打开记账。** 微信会清理自己的缓存，存里面的数据可能整份消失。请用系统浏览器（Safari / Chrome / Edge）打开，再「添加到主屏幕」。

### 2. 装到桌面（可选，但推荐）

- **iPhone**：Safari 打开 → 底部「分享」→「添加到主屏幕」
- **Android**：Chrome / Edge 打开 → 右上角菜单 →「安装应用 / 添加到主屏幕」
- **电脑**：Chrome / Edge 地址栏右侧的「安装」图标

装好后从桌面图标打开，全屏无浏览器条，断网也能用。

### 3. 先录商品，再记账

第一次用建议先花十分钟把常用的二三十个商品录进去（名称、规格、进价、售价、包装换算），之后开单只需要说一句话。

## 数据在哪 · 我不锁你

这是这个项目最想说清楚的一件事。

| 问题 | 答案 |
|---|---|
| 数据存在哪 | 你自己的浏览器（本机存储）；开了云同步的话，同步到**你自己注册的** Supabase 账号 |
| 作者能看到我的账吗 | **不能**。项目没有后端服务器，没有账号体系，不收集任何经营数据 |
| 要联网吗 | 不要。断网照常记账，联网后自动补同步 |
| 能导出吗 | 能。任何时候点「导出备份」得到一份完整 JSON，包含商品、流水、库存台账、往来、欠款、整单模板 |
| 我不用了能走吗 | 能。数据全在你手里，删掉文件就走，没有任何锁定 |

**导出格式是明文 JSON，不加密、不打包、不设门槛。** 这是有意为之——数据应该属于记录它的人。

> ⚠️ 但请记住：**你唯一需要负责的事，是定期备份。** 清理浏览器数据、换设备、手机丢失，本机数据都会没有。建议每月点一次「导出备份」，存到自己的网盘或电脑里。

## 功能

**记账**

- 一句话录单：`张三 螺母5个13元` → 自动拆行、识别客户名
- 连续记账：多件商品加入待结算清单，改完数量一次结算
- 整单模板：熟客常订的那批货存成模板，下次一点带入
- 进货速录：一行一件，支持从表格软件整列粘贴
- 退货、赊账、部分收款

**库存**

- 多单位换算（按盒进、按个卖），换算关系每个商品单独设
- 出入库总台账，与买卖记录双向联动
- 库存对账：以台账为基准反算应有库存，不一致可一键修正
- 库位管理、库存预警

**钱与往来**

- 现金流水（收入 / 支出 / 分类）
- 往来单位（客户 / 供应商）欠款台账、账期、对账单
- 首页经营概览：今日销售额、进货额、净利、应收欠款

**录单辅助**

- 拍照识别单据（百度 OCR / OCR.space / 本地 Tesseract，用自己的 Key）
- Excel 导入商品
- 拼音首字母速查（`ls` → 螺丝，`bx` → 扳手）

**数据**

- 导出 / 导入完整备份
- 可选云同步（自备 Supabase，多设备合并）
- 60 秒内撤销、修改历史

## 技术说明

给想读代码或二次开发的人：

| 项 | 情况 |
|---|---|
| 形态 | 单个 HTML 文件，CSS / JS 全部内联，**零外部依赖、零 CDN** |
| 体积 | 约 580 KB（未压缩） |
| 存储 | 浏览器 localStorage（前缀 `wb_wujin_`），约 5 MB 上限；图片存 Supabase Storage |
| 云同步 | 可选，用户自备 Supabase；合并策略 = 按 id 并集 + `_t` 时间戳后写优先，删除用墓碑标记防复活 |
| 测试 | **29 个套件 / 1870 条断言**，跑 `node tests/_dbg_audit.js` 全绿 |
| 静态检查 | `node tests/_check_edits.js` 校验关键编辑落盘；`_dbg_keys.js` 查幽灵存储键 |
| 安全 | 无 `eval` / `new Function` / `document.write`；所有 HTML 插值走 `esc()` / `jsStr()`，并有专门的转义回归套件 |
| 构建 | `node build_dist.js` 出干净版，`--demo` 出演示版 |

**为什么是单文件？** 因为它要能双击打开、能扔进任何静态托管、能在没有网络的店里活下去。代价是代码不能拆模块——这个取舍是有意的。

**测试怎么跑**

```bash
node tests/_dbg_audit.js      # 全量（约 40 秒）
node tests/_verify56.js       # 单个套件
```

新增套件需要同时接进 `tests/_dbg_audit.js` 的 suites 数组和 `.github/workflows/ci.yml`。

## 已知边界（诚实披露）

| 边界 | 说明 |
|---|---|
| 并发模型 | 「最终一致」而非强一致。多人同时改**同一件商品**，几秒窗口内可能有偏差；不同商品零冲突。单店共用账号场景实际极少撞上，兜底手段是「库存对账」 |
| 本机容量 | 浏览器 localStorage 约 5 MB，够存 1 万～1.5 万条流水；满了会明确提示，不会静默丢 |
| 发票税务 | **不做**。本工具不含发票开具、税务申报功能，不构成任何财税建议 |
| 多店隔离 | 不支持。设计前提是「一家店、几个人、共用一个账号」 |
| 微信内置浏览器 | **不支持**，见上文 |
| iOS 存储隔离 | Safari 与「已安装到主屏」的同一站点，本地数据可能互相看不到（iOS 系统行为）。换用时请以云端同步或导出备份为准 |
