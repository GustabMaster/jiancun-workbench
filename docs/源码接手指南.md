# 简存·单店进销存工作台 — 源码接手指南（面向审查/修改的 AI 或开发者）

> 用途：下一个接手本项目的 AI 或开发者，读此文档即可高效定位、审查、修改，避免踩已知坑。  
> 适用版本基线：`v1.15.32`（后续版本以 git tag 为准）  
> 最后更新：2026-10-18（开源整理：测试在 `tests/`，公开文档在 `docs/`）

---

## 一、项目一句话定位

单文件 HTML 进销存 + 出纳工作台，**全内联、零外链**（除一个 tesseract OCR 的 defer 外链，可选）。数据存浏览器 `localStorage`（前缀 `wb_wujin_`），可选同步到用户自有 Supabase 云端。已做 PWA（可安装、离线开）。

**黄金法则：永远保持"单文件、零外链、本地优先、云同步兜底"的架构，不要把它拆成多文件工程，除非用户明确要大改。**

## 三、核心数据模型（7 主表 + 墓碑 + 台账）

全部存 `localStorage`，键 = `wb_wujin_<name>`。

| 键（后缀）      | 内容                               | 关键字段要点                                                                                                         |
| ---------- | -------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `products` | 商品                               | `unit` 恒为"个"（基准，只读）；包装换算存 `conv`（对象 `{包装名: 等于多少个}`）；`stock` 当前库存；`safe` 安全库存；`cost/wholesale/retail` 成本/批发/零售价 |
| `cash`     | 出纳现金                             | 收支记录                                                                                                           |
| `flow`     | 买卖流水                             | 关联 `product`、`party`、`ar`（应收）                                                                                  |
| `parties`  | 往来单位                             | 供应商/客户；`debt` 欠款                                                                                               |
| `ar`       | 应收                               | 欠款明细                                                                                                           |
| `stockLog` | **出入库总台账**                       | `src`（manual/buy/sell/refund）、`fid` 关联流水、`pid` 关联商品、`_t` 同步戳。**库存变动的唯一权威来源**                                   |
| `todos`    | 待办                               | —                                                                                                              |
| `del`      | **删除墓碑**（权威键是 `del`，不是 `delLog`） | `{id,type,t}`，防止删除后云端重现                                                                                        |

**单位模型（第 80 轮重构，全局统一）：** 基准单位恒为"个"；多包装换算走 `conv`，"件"只是普通包装名，无特殊待遇。录入/报表单位下拉由 `conv` 动态生成，**禁止硬编码 盒/件/包/箱**。

## 四、版本体系（改动必看）

- `APP_VERSION`（约 L1140）：语义化 `主.次.修订`。整数=架构级，次=新功能，修订=修 bug。
- `VERSION_LOG`（约 L1141 起）：数组，每条 `{v, tag, desc}`。**设置页"版本更新"区倒序列出。**
- **T1 文案黑话禁忌**：`VERSION_LOG` 与设置页说明文案会被测试台 `jargon` 正则（含 `Supabase|WebSocket|_t|墓碑|NaN|localStorage|migrateUnits|conv|delLog|stockLog|云端面板|renderAll|SVG|断言|扫描台|渲染结果缓存|惰性|数据列内嵌` 等）扫描，**命中即测试 FAIL**。写版本说明必须用大白话（如"不合常理的坏值"代替"NaN/Infinity"）。

## 五、存储与同步机制（核心，改前必读）

### 5.1 本地读写

- `PREFIX='wb_wujin_'`（约 L1124）。`save(key,val)` / `load(key)` 封装 localStorage JSON。
- 本地 5MB 硬上限，作缓存；溢出时云端历史不丢（v1.13.18 起逻辑）。

### 5.2 云端同步（并集合并 + last-write-wins）

关键函数（行号随版本浮动，以 grep 为准）：

- `syncOnce(cb)`（≈L4866）：拉远端 → `mergeIntoLocal`。
- `mergeIntoLocal(remote)`（≈L4844）：按 id 并集 + `_t` 后改覆盖（平局取本地）。
- `mergeArr(local,remote)`（≈L4834）：数组级合并守卫（Array.isArray 兜底）。
- `tomb(id,type)`（≈L4809）/ `applyTombstones()`（≈L4810）：删除墓碑，"有墓碑默认删，仅当 `typeof r._t==='number' && r._t>t` 才保留"。
- `trimDelLog()`（≈L4808）：墓碑封顶 500 条，旧的丢弃。
- `startRealtime()`（≈L4888）：原生 WebSocket 直连 Supabase Realtime 广播（零外链），25s 心跳、断线 3s 重连。
- `schedulePush()`（≈L1206）：`save()` 内热防抖 2s 推云；`startCloudTimer` 每 30s 轮询兜底。
- **库存变动必须打 `_t`**：`commitFlow`/`commitRefund`/`saveFlowEdit`(原地)/`delFlow` 改 `product.stock` 后须 `p._t=Date.now()`，否则跨设备库存改动会在合并时被丢弃。

### 5.3 健壮性

- `autoHealthCheck()`（≈L4107）：开机扫描 7 表 + delLog，只修低级损坏（非有限数字→0、缺 id 补、缺 `_t` 补、非对象垃圾隔离、conv 非对象→`{}`），**不动业务一致性**；仅 `fixed>0||removed>0` 才保存 + 提示。整体 try 包裹不影响操作。
- 导入守卫 `importJSON`：`arr()=Array.isArray?x.filter(i=>i&&typeof i==='object'&&i.id):[]`，畸形/缺 id 一律丢弃。

## 六、PWA 相关（改动必读）

- `manifest.json`：name/display:standalone/start_url/icons（含 SVG + 192/512 PNG + apple-touch-icon）。
- `sw.js`：缓存名 `jiancun-shell-v1.15.31`，导航 network-first、离线回退缓存；`activate` 清旧缓存。
- HTML `<head>`：`<link rel="manifest">` + `theme-color` + `apple-touch-icon`。
- HTML 尾部主脚本内：`beforeinstallprompt` 捕获 → `deferredPrompt`；安装按钮 `btnInstallApp`（仅支持安装的浏览器显示）；一键更新 `checkUpdate()`（fetch 部署 `index.html` 解析 `APP_VERSION` 比对，有新版清壳缓存 reload）。
- **SW 注册块在主脚本内，全 `typeof` 守卫 + try/catch，仅 https 生效，file:// 不报错。**

## 七、对"下一个 AI"的审查清单

接手审查或修改前，逐项确认：

- [ ] 是否破坏单文件零外链（除 tesseract defer）？
- [ ] 是否动了 `conv`/单位模型却硬编码了包装名？
- [ ] 改库存路径是否补了 `p._t`？
- [ ] 删除函数是否接了墓碑 `tomb()`？
- [ ] 版本说明/设置页文案是否踩 T1 黑话正则？
- [ ] 是否新增了第二个纯 `<script>` 块（会破坏测试台，见下）？
- [ ] 改完是否重跑 `node tests/_dbg_audit.js` 全套件且零 FAIL？
- [ ] 是否同步 `deploy/` 并重新部署？
- [ ] 是否追加 `CHANGELOG.md` 并打 `git tag`？

## 八、改动禁忌（血的教训）

1. **不可引入第二个"纯 `<script>` 块"**：测试台 `tests/_bugscreen.js` 用贪婪正则 `<script>([\s\S]*)</script>`（L4）抓**首个开到最后一个闭**之间的全部内容喂给 vm。若新增第二个无属性的 `<script>`，捕获区间会夹入中间的 `</script>` 字面量，导致 `SyntaxError: Unexpected token '<'`，整个测试台崩。**正确做法：所有内联 JS 都并入应用主脚本内部（仅保留一对 `<script>`）；外部依赖只能用带 `src` 或带 `id` 属性的标签。**
2. **不可破坏脚本标签配对**：全文件应仅"应用主脚本一对 + tesseract 外链单行"共 3 行 `<script>` 相关。改动后 grep 确认。
3. **不可硬编码单位名**：盒/件/包/箱/条/根/套 一律由 `conv` 动态生成。
4. **不可删 `try/catch` 守卫**：SW 注册、同步、自检全有 try 包裹，删了会让 file:// 或异常环境崩。
5. **不可把密钥硬编码进源码**：Supabase key 由用户配置存本地。

## 九、测试台用法

```bash
# 一键全套回归（务必零 FAIL；从仓库根目录运行）
node tests/_dbg_audit.js   # 29 套件 1870 断言；末尾看「合计: 1870 PASS / 0 FAIL」

# 单个套件按需跑，例如：
node tests/_bugscreen.js   # 519 断言：健壮性/同步/单位/删除/自检
node tests/_verify56.js    # 389 断言：业务链路主回归
node tests/_check_edits.js # 核查批量数值加固编辑是否真实落盘

# 跑完看末尾"结果：X PASS / 0 FAIL"；grep 到 "FAIL" 行即失败
```

- 测试台用 `vm` 模拟 document/localStorage/alert/FileReader，`__api` shim 白名单桥接内部全局（如 `api.products`）；未在白名单的顶层函数（如 `autoHealthCheck`/`syncOnce`/`renderVersionLog`）必须经 `ctx.` 调用，不能 `api.`。
- 结果行若有"0 FAIL"字面被 grep 命中属正常，看 PASS 数与真实 FAIL 行判断。
- 套件源码路径统一吃 `process.argv[2]||'wujin-workbench.html'`，默认从仓库根目录跑。
- `tests/_archive/` 内是历史死套件，**不要跑、不要当失败**。

## 十、回退点与发布流程

1. 改前：`git status` 确认干净，确认存在上一个 `tag`（如 `v1.15.31`）。
2. 改完：升 `APP_VERSION` + 追加 `VERSION_LOG` + `CHANGELOG.md`。
3. 跑 `node tests/_dbg_audit.js` 零 FAIL。
4. `cp wujin-workbench.html deploy/index.html`（含 manifest/sw/icon 一并 cp）。
5. 部署到固定沙箱 `bb7ac5ada7b241bdb5af785ae37c73f2`（端口 3000，链接不变）。
6. `git add -A && git commit -m "..." && git tag vX.Y.Z`。
7. 回退：`git checkout vX.Y.Z` → 重新 cp + 部署。
